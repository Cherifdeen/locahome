================================================================================
                    PROJET LOCAHOME - PLAN DE DÉVELOPPEMENT
              Mise à jour vers plateforme multi-propriétaires
================================================================================

Ce plan détaille les modifications à apporter au projet existant pour le
transformer en plateforme multi-propriétaires avec vitrine publique.

================================================================================
                    PHASE 1 - REFONTE DE L'ARCHITECTURE
================================================================================

1.1. NOUVEAUX MODÈLES À CRÉER

A. App "comptes" - Gestion des propriétaires
   □ Créer l'app Django "comptes"
   □ Modèle Proprietaire :
     - user (OneToOne vers User Django)
     - nom_complet
     - telephone
     - email
     - date_inscription
   □ Configuration de l'authentification (inscription, connexion, déconnexion)

B. App "maisons" - Nouveau module
   □ Créer l'app Django "maisons"
   □ Modèle Maison :
     - proprietaire (ForeignKey vers Proprietaire)
     - nom
     - quartier
     - type_maison (studio, appartement, maison, etc.)
     - adresse
     - description
     - photo (optionnel)
     - cree_le, mis_a_jour_le
   □ Méthodes : nombre_chambres_libres, nombre_chambres_total

--------------------------------------------------------------------------------

1.2. MODIFICATIONS DES MODÈLES EXISTANTS

A. Modèle Chambre (chambres/models.py)
   □ Ajouter : maison (ForeignKey vers Maison) - OBLIGATOIRE
   □ Supprimer la relation directe avec propriétaire (via maison maintenant)
   □ Le statut reste (LIBRE/OCCUPEE) mais la logique change

B. Modèle Locataire (locataires/models.py)
   □ Ajouter : caution_eau (DecimalField) - montant payé
   □ Ajouter : avance_loyer devient la garantie (X mois)
   □ Ajouter : avance_initiale (pour garder trace du montant initial)
   □ Modifier la logique de calcul des retards → soustraction auto dans avance

C. Modèle Paiement (paiements/models.py)
   □ Ajouter type : FORMALITES (pour avance + caution eau)
   □ Ajouter : details_formalites (JSON ou champs séparés)
   □ Garder les types : ENTREE (1er mois), MENSUEL, SORTIE

D. Modèle ProprietaireParametres → devient ParametresProprietaire
   □ Ajouter : proprietaire (ForeignKey vers Proprietaire)
   □ Ajouter : nombre_mois_avance (IntegerField, défaut=3)
   □ Ajouter : montant_caution_eau (DecimalField)
   □ Chaque propriétaire a ses propres paramètres

Ensuite pour l'entrée on n'est pas obligée de forcément enregistrer un locataire avant de pouvoir effectuer un paiement en son nom. On va faire un changement: Sur la page locataire on va enlever le boutton "Ajouter un locataire" car temps que la personne n'a pas payé l'avance puis le premier paiement il ne peut pas être considéré comme locataire. Sur la page locataire on n'aura de la liste des locataires. Sur la page paiement, lorsqu'on clique sur entrée on a un formulaire qui demande les informations du nouveau locataire(ancien formulaire de "Ajouter un locataire"), une fois ce formulaire validé, on est dirigé sur le formulaire de paiement d'avance puis sur celui de paiement du premier mois. Ce n'est qu'apres validation de ce dernier paiement que ce locataire pourra apparaitre dans la liste des locataires.
Le filtre au niveau de locataire aussi ne fonctionne pas correctement
